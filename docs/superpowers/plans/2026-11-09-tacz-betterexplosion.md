# TaCZ Better Explosion Implementation Plan (M1 + M2)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace TaCZ's explosion damage with a wider cover-aware model and its vanilla visuals with a layered, performance-budgeted effect system.

**Architecture:** One Mixin cancels `ExplodeUtil.createExplosion`; `BetterExplosions.detonate` runs a block pass (TaCZ's own `ProjectileExplosion`, entities emptied), our own damage pass, and sends one S2C `ExplosionFx` packet. The client turns that packet into budgeted particles, sounds, shake and flash. All maths (damage, tiers, budgets, codec) is pure Java so it is unit-tested without Minecraft.

**Tech Stack:** Java 17, Forge 47.4.0 (MC 1.20.1, Parchment mappings), Mixin 0.8.5, JUnit 5, Python 3 + Pillow (texture generation only).

**Spec:** `docs/superpowers/specs/2026-11-09-tacz-betterexplosion-design.md`. M3 (underwater variant, LOD tuning from measurements, TaCZ Tweaks compat) gets its own plan after M2 measurements.

## Global Constraints

- Minecraft 1.20.1, Forge 47.4.0, Java 17. Project dir: `1.20.1-forge`. Build: `gradlew build`.
- TaCZ range in `mods.toml`: `[1.1.7,)` (hook verified in 1.1.7-hotfix2 and 1.1.8-hotfix2). Mixin uses `remap = false` and `require = 1`.
- Mod required on server and client; `SimpleChannel` with a strict version string.
- No SBW code or assets. All textures are original, generated by `tools/gen_textures.py`.
- Block behaviour stays TaCZ's. After the mixin cancels, a failure in any pass is logged and never falls back to TaCZ's original.
- `net.minecraft.client`, `com.mojang.blaze3d` and `net.minecraftforge.client` appear only under package `...tacz_betterexplosion.client`.
- Defaults: server `enabled=true, reachMultiplier=2.0, coverFloor=0.25, damageMultiplier=1.0, knockbackMultiplier=1.0, maxTargets=128`; client `quality=HIGH, maxLiveParticles=700, adaptiveQuality=true, screenShake=true, shakeStrength=1.0, screenFlash=true`. Getters return these while the spec is not loaded.
- Tier table (`radius <`, budget, packet range, particle range): MINI 2/12/64/48, SMALL 3.5/28/96/64, MEDIUM 6/55/160/96, LARGE 10/90/224/144, HUGE inf/150/256/192.
- Commits use the existing global git identity (Hoeng Reaksa). Plain messages, no bot trailers, never push.

## Review Focus

1. `radius` or `damage` is 0, negative or NaN (bad gunpack data): no damage, no exception (Task 1).
2. Target exactly at the blast centre (zero direction vector): no NaN knockback (Task 1).
3. Packet radius NaN, negative or huge: tier MINI, MINI, HUGE (Task 2).
4. `Minecraft.getFps()` returns 0 on the first frames: must not trigger throttling (Task 6).
5. Live-particle cap already exceeded (config lowered at runtime): budget 0, never negative (Task 6).

Also by design, not unit-testable: a null `owner` (dispenser, owner logged out) must not NPE; `DamageSources.explosion(Entity, Entity)` accepts null, and `ExplosionContext.owner` is `@Nullable`.

  - `static EnumMap<Layer,Integer> split(int budget)`: RING fixed 1, FLASH fixed 2 (both clamped to what the budget allows, in priority FLASH, RING), remainder shared FIREBALL 0.30, STEM 0.30, DUST 0.12, DEBRIS 0.14, SPARKS 0.14; sum never exceeds `budget`
